# 需求卡：ppt-agent

## 一句话

输入一份 brief（主题、受众、目标、要点、页数、主题色），输出一份可直接编辑的 16:9 PPTX，同时给出 HTML 预览、Markdown 讲稿与质检报告。

## 谁用

- 主要：自己与同事，用于内部汇报、项目复盘、方案与售前材料。
- 次要：被其他脚本或上层工作流调用（`eval` 与 `pipeline` 都是稳定入口）。
- 不面向：需要多人实时协作的在线编辑场景——本版不做 Web 编辑器。

## 什么触发

- 命令行手动跑：`make run`、`python3 src/ppt.py ...`。
- 被脚本调用：stdin 传 JSON、stdout 收 JSON 的 `eval` 入口。
- 不常驻、不监听端口、不写外部系统。

## 输入什么

| 项 | 说明 |
|---|---|
| 主题 | 必填，≤80 字 |
| 受众 / 目标 / 讲者 / 日期 | 选填，进入封面与讲稿语气 |
| 页数 | 3–30，默认 10 |
| 要点 | 0–12 条，每条 ≤60 字；也可给 2–6 个自定义章节 |
| 主题色 | `swiss` / `ocean` / `warm` / `ink`，或自定义主题 JSON |
| 图片 | 仅 `image` 版式需要，传本地路径 |
| 语言 | `zh` / `en` |

不接收 PII 之外的敏感数据；密钥只从环境变量读，不落盘、不入库。

## 输出什么算对

1. 页数与 brief 完全一致（3–30）。
2. 第一页是 `title`，最后一页是 `closing`。
3. 每页标题 ≤34 字宽（封面 ≤44）；要点 ≤5 条，单条 ≤56 字宽。
4. 所有文本在版心内不溢出（按 1.32 行高、CJK 1 em 估算，偏保守）。
5. 每页有 ≥20 字讲稿备注，整套讲稿覆盖率 100%。
6. PPTX 能被 python-pptx 回读，页数、标题、备注与 `deck.json` 一致。
7. 离线 mock 模式下 37 条评测全绿；两次运行通过率波动 ≤5 个百分点。
8. 质检有阻断项时退出码为 1，并给出 `code` + `hint`，不静默降级。

## 错了的代价

- 只读产出：不写数据库、不发消息、不改外部状态，最坏是重跑一次。
- 若直接发给客户：版式溢出、标题压字、事实错误会带来声誉成本。因此这类问题必须阻断，而不是“看起来还行就放行”。

## 非目标（本版不做）

- 不做在线编辑器与拖拽排版。
- 不做配图生成、图库检索与图表（chart）渲染。
- 不从用户上传的 PPTX 反推模板版式（PPTAgent 的模板归纳路线）。
- 不做多模态视觉评审；v1 用几何测量 + 结构检查代替。
- 不做多 agent 协作；单 agent + 明确流水线足够。

## 5 条真实样例

1. 9 页内部汇报：AI 编程助手试点，受众研发管理者，目标“下季度试点”。
2. 3 页电梯简报：只讲结论、一个数字、一个请求。
3. 30 页季度复盘：按结果、问题、计划三章展开，含 4 组 KPI。
4. 9 页英文 pitch：受众海外工程负责人，主题为 AI coding assistant。
5. 负例：80 字超长主题 + 无要点 + 页数 2——必须在入口报错，而不是生成一份烂稿。
